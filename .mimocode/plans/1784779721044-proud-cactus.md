# Plan: Locale-aware prompts + clean variable UI

## Goal
1. Remove technical variable names (`{{user_idea}}`) from prompt settings UI — show only translated descriptions
2. Make LLM prompt templates locale-aware so users can write novels in the interface language (zh-CN, en, ru)

## Task 1: Remove `{{varName}}` from variable buttons

**File**: `src/components/settings/PromptSettings.tsx` (lines 264-266)

Current code shows both `{{varName}}` and description:
```tsx

<span className="opacity-60 max-w-[200px] truncate">{translatedDesc}</span>
```


Keep `insertVariable(varName)` on click — the `{{varName}}` is still inserted into the textarea, just not displayed on the button.

## Task 2: Make prompt templates locale-aware

### Approach
Add a `contentLocalized` field to `PromptTemplate` that contains translations of the prompt body. The rendering system selects the right version based on `i18n.language`.

### 2.1 Update PromptTemplate interface

**File**: `src/services/prompt-templates.ts`

Add optional field:
```typescript
export interface PromptTemplate {
  // ... existing fields
  /** Localized content overrides keyed by locale (zh-CN, en, ru) */
  contentLocalized?: Record<string, string>
  /** Localized systemRole overrides */
  systemRoleLocalized?: Record<string, string>
  /** Localized systemSuffix overrides */
  systemSuffixLocalized?: Record<string, string>
}
```

### 2.2 Create locale-aware getter functions

**File**: `src/services/prompt-templates.ts`

Add functions:
```typescript
function getLocalizedContent(template: PromptTemplate): string {
  const lang = i18n.language
  return template.contentLocalized?.[lang] || template.contentLocalized?.[lang.split('-')[0]] || template.content
}

function getLocalizedSystemRole(template: PromptTemplate): string {
  const lang = i18n.language
  return template.systemRoleLocalized?.[lang] || template.systemRoleLocalized?.[lang.split('-()[0]] || template.systemRole || ''
}

function getLocalizedSystemSuffix(template: PromptTemplate): string {
  const lang = i18n.language
  return template.systemSuffixLocalized?.[lang] || template.systemSuffixLocalized?.[lang.split('-')[0]] || template.systemSuffix || ''
}
```

## Key design decisions
- Keep `content` field as Chinese default (backward compatibility)
- Add `contentLocalized`, `systemRoleLocalized`, `systemSuffixLocalized` optional fields
- `systemSuffix` (JSON schema) stays Chinese for parsing — only `content` and `systemRole` are translated
- Variable `{{varNames}}` in templates stay as-is — they're replaced at runtime regardless of locale
- The textarea in PromptSettings shows the localized version so users see what they're editing
